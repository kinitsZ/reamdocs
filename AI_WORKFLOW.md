## Tools used

- **Claude Design** for the initial UI mockup (`Ream Docs.dc.html` in the design
  handoff) — five screens plus two modals, iterated on before any code existed.
- **Claude Code** for the full-stack implementation: schema, API routes, auth,
  editor wiring, sharing, import pipeline, tests, and this documentation.

## Where AI materially sped things up

- **Turning a static HTML/CSS mockup into a real app.** The mockup was built with
  a prototyping tool's own templating runtime (`support.js`), not React. Claude
  Code read it, extracted the actual design intent (tokens, layout, copy,
  interaction model) rather than porting the prototype's internal structure, and
  flagged the parts that don't survive contact with a real app *before* writing
  code (see "design inconsistencies" below) instead of silently reimplementing a
  design-tool artifact as a real feature.
- **Reading version-specific docs before writing code, twice.** This repo's
  `AGENTS.md` (auto-generated by `next dev`) explicitly warns that this Next.js
  version has training-data-breaking changes and to read the bundled docs first.
  `npm install` also resolved Prisma to a CLI/client version mismatch (8.0.0-rc
  vs 6.x) and Zod to v4. Claude Code fetched the actual Next.js 16 upgrade guide,
  Prisma's 6→7 breaking-changes doc, and Zod's v4 changelog before writing schema
  code or API routes, rather than assuming APIs it was trained on still applied —
  this caught real breaking changes (async `cookies()`/`params`, Prisma 7's
  mandatory driver adapters, Zod's `z.email()` becoming a top-level function).
- **Diagnosing a local network issue methodically instead of guessing.** Prisma
  couldn't reach Supabase. Rather than trial-and-error editing the connection
  string, it isolated the cause with layered network tests (DNS resolution → TCP
  handshake → raw protocol bytes → a control test against an unrelated host on
  the same port) and landed on "this router blocks outbound Postgres ports,"
  then produced an offline workaround (SQL files runnable from Supabase's web
  editor, which only needs HTTPS) instead of stalling on it.
- **Boilerplate that would otherwise eat the clock**: Prisma schema + idempotent
  seed script, Zod validation schemas, the access-control unit tests, and the
  Tailwind styling translation from the mockup's inline `oklch()` values into
  reusable CSS custom properties.

## What I changed or rejected from the AI's output

- **Design inconsistencies the AI flagged, that I decided on**: dropping the
  mockup's "States" nav tab (a design-review artifact, not a real screen),
  dropping fake live-presence avatars, and collapsing two file-upload concepts
  (import-as-new-doc vs. attach-and-insert) into one. These were the AI's
  recommendations; I confirmed them rather than let the build proceed on
  assumption — see the chat history for that checkpoint.
- **Prisma version pin.** Left as recommended (6.19.3) rather than adopting the
  newer major versions the registry defaulted to — a case where the more
  cautious, less impressive-sounding choice was the right call under a time box.

## How correctness, UX, and reliability were verified

- **Type checking and linting** (`tsc --noEmit`, `eslint`) run clean after each
  major addition, not just at the end.
- **Automated tests** (`npm test`, Vitest) cover the access-control matrix
  (owner/editor/viewer/stranger × view/edit) and file-import validation
  (accepted extensions, size cap, empty files) — the two places a silent bug
  would be worst, per `ARCHITECTURE.md`.
- **A real production build** (`next build`) was run and passed, not just `next
  dev`, to catch anything that only surfaces under strict build-time checks.
- **A local server smoke test** confirmed the app boots and non-DB routes work
  correctly (`/` redirects appropriately), and that the DB-dependent failure
  mode is exactly the expected network error rather than an application bug —
  distinguishing "my code is wrong" from "this network blocks port 5432" before
  concluding either way.
